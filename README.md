# 按 ID 回复限额

允许与指定账号有限交流，避免两个机器人互相 @后持续聊天。默认 **每个群、每个登记账号，30 分钟内最多回复 3 轮**。仅支持 QQ OneBot v11（`aiocqhttp`，可搭配 NapCat），当前兼容范围为 AstrBot **4.29.3**。

## 安装与配置

AstrBot 插件管理 → 安装插件 → 从文件安装，选择完整 ZIP。安装后打开本插件的配置：

| 选项 | 填写方式 |
| --- | --- |
| 启用限额 | 开启 |
| 登记ID | 对方真实 QQ 号，每行一个；空列表不限制任何人 |
| 统计秒数 | `1800` 为半小时，`3600` 为一小时 |
| 回复上限 | 默认 `3`，必须为正整数 |
| 生效群 | 群号，每行一个；留空适用于所有 QQ 群 |

同一配置中的登记账号使用相同的窗口和上限，各自独立计数。不同机器人实例、机器人账号、群和对方账号互不占用额度。私聊、未登记的普通群友和 AstrBot 配置的管理员不受限；QQ 群主或群管理员身份不自动获得豁免。

## 什么算一轮

对一条输入实际发出回答，计一轮。普通接话、@、关键词和引用触发使用同一额度；一条回答分成几个消息气泡、包含文字和图片，也只计一轮。仅收到消息但没有回复不计数，模型路由和内部工具调用不计数。

生成中的请求预占名额，防止并发越过上限。消息被其他插件拦截、模型失败、取消或整轮未发送时释放名额。达到上限后直接忽略该账号的新消息，不调用下游回答流程，不发送“冷却中”提示，也不排队补发。

这是滑动窗口，不是整点清零。例如 10:00、10:05、10:10 各回复一轮，半小时三轮配置下，最早在 10:30 恢复一个名额，10:35 再恢复一个。窗口从成功发送首段的时间计算。

## 与其他插件配合

- **Chat Plus** 继续决定是否接话，本插件只限制最多回复多少轮，不强制用满额度。
- **证据问答与会话路由** 的群总量限制继续有效：群额度和对象额度都允许时才回答。因群总量或主人暂停而未发送的回答，不扣对象额度。
- **免冷却群** 不会自动豁免本插件。若某群不需要按 ID 限额，将「生效群」设为需要限制的其他群。
- **LivingMemory / 型号检索** 无需改变配置。超额消息在插件处理前停止，因此也不会交给后续消息监听器采集记忆；已有记忆不变。
- 其他插件若直接屏蔽同一账号，该账号仍不会得到回复。需要有限互动时，应关闭对它的直接屏蔽。

## 运行与兼容

无需 API、额外 Python 依赖或数据库。仅在内存保存时间戳和计数，不保存聊天正文。重载或重启插件会重置额度。

插件在 `ProcessStage.process` 前登记额度，用 `AiocqhttpMessageEvent.send` 的成功发送标记计数，在 `PipelineScheduler.execute` 结束时释放未发送名额。这三个适配入口依赖 AstrBot 4.29.3 内部实现；升级 AstrBot 后需复核兼容性。停用时恢复自己仍持有的入口，不覆盖其他插件后来安装的包装。

覆盖正常 AstrBot 群消息流程，以及该轮通过消息事件发送的回答；其他插件绕过消息事件直接调用 OneBot、独立定时发送或跨群转发不在此限额范围内。一轮分三条仍只算一次，限制轮数不等于限制消息气泡总数。

## 手动验证

1. 在测试群登记测试账号，暂设 `60` 秒、`3` 轮。
2. 让其通过普通唤醒、@和关键词依次触发三次回答，第四次应保持沉默。
3. 换未登记账号提问，应正常；换群后登记账号的额度独立。
4. 首次回答满 60 秒后，重新发一条消息，应恢复一个名额，之前被忽略的消息不补发。
5. 恢复 `1800` 或 `3600` 秒，再保存。

## 来源与许可

按对象限额的需求来自多机器人有限互动场景。滑动窗口和并发预占设计沿用同作者的[证据问答与会话路由](https://github.com/Tritium-33/astrbot_plugin_evidence_qa)，本插件独立运行，不依赖该项目。未复制第三方多机器人唤醒优化插件的实现。
